# Курс C / C++ — как мы работаем

Обучение через твой репозиторий `St1Rner-ded/myeducational`.
Приоритет — **задачи**, теория выдаётся порциями ровно под задачу.

## Роли

| Кто | Что делает |
|---|---|
| **Ты** | решаешь задачи локально (или в онлайн-компиляторе), коммитишь решения в репо |
| **Я** | тяну репо, компилирую твои решения со строгими флагами и санитайзерами, гоняю тесты, делаю ревью кода, даю теорию и следующую пачку задач |

Обратно в GitHub я писать не могу (нет креденшелов), поэтому всё, что я произвожу,
ложится в workspace и отдаётся тебе файлами.

## Структура репозитория (создай у себя)

```
myeducational/
├── solutions/
│   ├── answers_A.md        ← ответы на часть A диагностики (с пояснениями!)
│   ├── L0/
│   │   ├── L0-T1.cpp
│   │   ├── L0-T2.cpp
│   │   └── L0-T3.cpp
│   ├── L1/ ...
│   └── L2/ ...
└── notes/                  ← твои вопросы, заметки, «не понял вот это»
```

Имя файла = ID задачи. Один файл = одна задача. Коммит — по факту решения
(можно коммитить и нерешённое: я увижу, где затык).

## Протокол хода

1. Ты коммитишь решения → пишешь мне «проверь» (или задаёшь вопрос).
2. Я запускаю `./check.sh`: pull репо → компиляция → warnings → ASan/UBSan → тесты.
3. Ты получаешь отчёт: ✅ принято / ⚠️ работает, но код плохой / ❌ не прошло + разбор.
4. Даю следующую пачку задач и теорию.

## Флаги компиляции — привыкай сразу

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -g \
    -fsanitize=address,undefined main.cpp -o app && ./app
```

* `-Wall -Wextra -Wpedantic` — предупреждения. **Ноль предупреждений** — это норма, а не педантизм.
* `-g` + `-fsanitize=address,undefined` — ловит выход за границы, use-after-free,
  переполнения, UB. На учёбе включать всегда. В релизе — нет (медленно).
* Для C: `gcc -std=c11 ...` те же флаги.

Сделать алиас, чтобы не набирать каждый раз:

```bash
alias cxx='g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -g -fsanitize=address,undefined'
alias cc='gcc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -g -fsanitize=address,undefined'
```

## Правила, которые реально ускоряют обучение

1. **Правило 25 минут.** Застрял дольше — не ищи готовое решение. Напиши в
   `notes/`: что пробовал, что выводит, где именно непонятно. Я дам подсказку
   нужного размера (не ответ).
2. **Не давай ИИ писать решения за тебя.** Объяснять, разбирать ошибки,
   показывать альтернативы — да. Писать решение до твоей попытки — нет,
   иначе через месяц не сможешь повторить без подсказки.
3. **Сначала на бумаге.** Прежде чем кодить: вход, выход, инвариант, крайние случаи
   (пусто, ноль, отрицательное, максимум типа, дубликаты).
4. **Пересобирай пройденное.** Раз в неделю — решить старую задачу заново с нуля,
   без подглядывания. Это то, что превращает «понимаю» в «умею».
5. **Читай ошибки компилятора сверху вниз.** Первая ошибка обычно причина,
   остальные — следствия.

## Справочник

`cpp-course/SPRAVOCHNIK.md` — **единый живой документ** со всеми таблицами и шпаргалками
(типы и их границы, спецификаторы printf, указатели, UB, битовые операции, выравнивание,
флаги компиляции, gdb, git, make, словарь терминов).

Держи его в корне репозитория как `SPRAVOCHNIK.md` — тогда он открывается на GitHub
с любого устройства. Я пополняю его по мере прохождения модулей и bump'аю версию;
что именно добавилось — смотри в разделе «Журнал изменений» в конце файла.

Обновление у себя:
```bash
# скачать новую версию из чата, положить в корень репо и:
git add SPRAVOCHNIK.md && git commit -m "spravochnik vX.Y" && git push
```

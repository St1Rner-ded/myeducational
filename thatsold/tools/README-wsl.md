# Как переносить файлы из Windows в WSL и сразу в git

Проблема: ты скачиваешь файл в чате — он попадает в `C:\Users\…\Downloads`,
а репозиторий живёт внутри WSL. Ниже четыре способа, от «ничего не настраивать»
до полной автоматизации.

⚠️ **Главное правило:** проект должен лежать **внутри** файловой системы Linux
(`~/projects/…`), а не в `/mnt/c/…`. Работа с `/mnt/c` из Linux в разы медленнее,
и `git status` на таком репо тормозит заметно.

---

## Способ 1 · Drag-and-drop в VS Code (ноль настройки)

У тебя VS Code уже подключён к WSL. Значит:

1. Открой в VS Code папку репозитория (из терминала WSL: `cd ~/projects/myeducational && code .`).
2. Перетащи файл из Проводника Windows прямо в панель **Explorer** слева.
3. VS Code скопирует его в файловую систему WSL, в открытую папку.

Работает и для папок, и для нескольких файлов сразу. Для разовых операций — лучший вариант.

---

## Способ 2 · Проводник Windows видит файлы WSL (ноль настройки)

WSL отдаёт свою файловую систему по сети. В адресной строке Проводника:

```
\\wsl.localhost\Ubuntu\home\ТВОЙ_ЛОГИН\projects\myeducational
```

(на старых сборках Windows — `\\wsl$\Ubuntu\…`). Дальше обычное «копировать/вставить»
из Загрузок.

Тот же путь из терминала WSL:

```bash
explorer.exe .          # открыть ТЕКУЩУЮ папку в Проводнике Windows
explorer.exe ~/projects # открыть домашнюю
```

Узнать точный путь к себе: `wslpath -w ~` покажет вид этого пути для Windows.

---

## Способ 3 · Скрипт `take` (автоматизация, рекомендуется)

Одна команда: берёт всё новое из Загрузок Windows, распаковывает `.zip`
в корень репозитория (мои архивы собраны именно под это), показывает `git status`
и — по флагу — коммитит и пушит.

### Установка (один раз)

Файл `take.sh` лежит в архиве `wsl-tools.zip`, который ты скачаешь. Перенеси его
в WSL любым способом выше, затем:

```bash
mkdir -p ~/bin
cp /mnt/c/Users/*/Downloads/take.sh ~/bin/take   # или путь, куда положил
chmod +x ~/bin/take
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
take --list          # проверка: должно показать, что нового в Загрузках
```

Если `cp /mnt/c/Users/*/Downloads/...` ругается — посмотри `ls /mnt/c/Users/`,
там будет твоё имя пользователя Windows, и подставь его в путь явно.

Дополнительно (не обязательно, но удобно):

```bash
sudo apt install unzip     # иначе скрипт распакует zip через python3 — тоже работает
```

### Использование

| Команда | Что делает |
|---|---|
| `take` | забрать всё новое, распаковать zip, показать `git status` |
| `take --list` | только показать, что появилось (ничего не трогает) |
| `take --ship` | то же, что `take`, **+ `git add -A` + commit + push** |
| `take --move` | убрать забранное из Загрузок (по умолчанию — копирует) |
| `take --all` | взять всё заново, игнорируя память о уже забранном |
| `take --dest solutions/M2` | положить не в корень, а в указанную папку |
| `take --keep-zip` | не распаковывать `.zip`, положить архивом |
| `take --reset` | очистить память о забранных файлах |

Обычный цикл выглядит так:

```bash
take --ship      # и всё. Файлы из чата уже в репозитории на GitHub.
```

### Как скрипт понимает, что «новое»

Он хранит список уже забранных файлов (имя + размер + время изменения) в
`~/.take_state`. Поэтому повторно один и тот же файл не копируется, а скачанный
заново или изменённый — копируется. Забранные при `--move` складываются в
`~/.take_taken`, а не удаляются.

### Автопоиск путей

**Загрузки.** Перебирает `/mnt/c/Users/*/Downloads`, пропуская `Public`, `Default`,
`All Users`. Берёт первую найденную папку.

**Репозиторий.** Ищет по порядку:
1. переменная `TAKE_REPO`, если задана;
2. путь, запомненный в `~/.take_conf` с прошлого успешного запуска;
3. текущая папка и её предки (поэтому `cd` в репо и `take` — всегда работает);
4. обход `$HOME` на глубину до 5 каталогов — ищет `.git`, у которого в remote
   указан `myeducational`.

Найденный путь запоминается в `~/.take_conf`, так что после первого запуска
`take` работает из любой директории. Проверить/поправить вручную:

```bash
cat ~/.take_conf                                   # что запомнил
echo ~/projects/myeducational > ~/.take_conf       # задать явно
rm ~/.take_conf                                    # забыть и искать заново
```

Если не нашлось — задай пути разово через переменные окружения:

```bash
TAKE_DOWNLOADS="/mnt/c/Users/Имя/Downloads" TAKE_REPO=~/projects/myeducational take
```

### Ярлыки для двойного клика в Windows

В архиве два файла:

- **`take.cmd`** — двойной клик: забрать всё новое и запушить
- **`take-list.cmd`** — двойной клик: только посмотреть, что нового

Положи их, например, на Рабочий стол. Внутри они просто вызывают
`wsl.exe -e bash -lc "~/bin/take ..."`.

Если у тебя несколько дистрибутивов WSL, поправь первую строку:
`wsl.exe -d Ubuntu -e bash -lc "~/bin/take --ship"` (имя дистра смотри в `wsl -l -v`).

## Способ 4 · Из интернета напрямую в WSL

Если файл где-то лежит по ссылке — скачивай сразу в Linux, минуя Windows:

```bash
cd ~/projects/myeducational
wget https://example.com/file.zip      # или curl -O
python3 -m zipfile -e file.zip .       # распаковать, если нет unzip
```

---

## Обратная сторона: достать файл ИЗ WSL в Windows

```bash
explorer.exe .                                   # открыть папку в Проводнике
cp SPRAVOCHNIK.md /mnt/c/Users/Имя/Downloads/    # скопировать в Загрузки
```

## Частые проблемы

| Симптом | Решение |
|---|---|
| `take: command not found` | не подхватился PATH: `source ~/.bashrc`, либо запускай `~/bin/take` |
| «Не нашёл папку Загрузки» | `ls /mnt/c/Users/` → задай `TAKE_DOWNLOADS=...`; если `/mnt/c` пуст — `sudo mkdir /mnt/c && sudo mount -t drvfs C: /mnt/c` |
| «Не нашёл репозиторий» | `cd` в папку репо и запусти `take` оттуда, либо `echo ~/путь/к/myeducational > ~/.take_conf` |
| `unzip: command not found` | скрипт сам переключится на `python3 -m zipfile`; либо `sudo apt install unzip` |
| push спрашивает логин/пароль | пароль от GitHub больше не принимается — нужен Personal Access Token, либо SSH-ключ. Скажи, помогу настроить |
| `.cmd` открывается блокнотом | правый клик → «Открыть с помощью» → выбрать программу, либо положи в папку и запусти двойным кликом из Проводника |
| В `.cmd` кракозябры вместо русского | консоль в другой кодировке; в файле уже стоит `chcp 65001`, обычно помогает перезапуск |
| Файлы в репо попали, но `git status` пуст | значит они совпали с уже имеющимися — всё в порядке |

# Указатели — с нуля и до «а, так вот оно что»

Ты написал: «мне явно надо побольше инфы про эти указатели чертовы, звездочки
амперсанды емае». Это правильный диагноз: указатели — единственная тема, которая
держит сразу четыре твоих пробела (A6, A7, P2, P4) и без которой не пойдут ни
M2-T2 (`unpack_date`), ни весь модуль 4 про память.

Все примеры здесь **скомпилированы и запущены** gcc 12.2. Вывод настоящий.
Адреса у тебя будут другие и будут меняться при каждом запуске — это нормально.

---

## 0. Одна мысль, на которой держится всё

> **Указатель — это переменная, в которой лежит адрес другой переменной.**

Не индекс. Не значение. Не «ссылка на объект» в бытовом смысле. Просто **число** —
номер байта в памяти, начиная с которого лежит то, что тебе нужно.

Всё остальное — следствия.

---

## 1. Память — это лента пронумерованных байтов

```
адрес (номер байта)      содержимое
   ...
   0x7ffd879b5f58   ┌──┬──┬──┬──┬──┬──┬──┬──┐   ← здесь живёт p
                    │64│5f│9b│87│fd│7f│00│00│      (8 байт: сам адрес x)
                    └──┴──┴──┴──┴──┴──┴──┴──┘
   0x7ffd879b5f64   ┌──┬──┬──┬──┐               ← здесь живёт x
                    │2A│00│00│00│                  (4 байта: число 42)
                    └──┴──┴──┴──┘
   ...
```

`x` — это не «42», это **имя для ячейки по адресу `0x7ffd879b5f64`**, в которой
лежит 42. Указатель `p` — это ячейка по другому адресу, в которую записано число
`0x7ffd879b5f64`.

---

## 2. Две операции: `&` и `*`

| Запись | Читается как | Что делает |
|---|---|---|
| `&x` | «адрес x» | выдаёт номер ячейки, где лежит `x` |
| `*p` | «значение по адресу p» | идёт по адресу и читает/пишет туда |

```c
int x = 42;
int *p = &x;      // p = адрес x
*p = 100;         // записали 100 ТУДА, куда указывает p, то есть в x
printf("%d\n", x);   // 100
```

### Главная причина путаницы: у звёздочки ДВЕ разные роли

```c
int *p;     // здесь * — ЧАСТЬ ТИПА: «p имеет тип указатель на int»
*p = 5;     // здесь * — ОПЕРАЦИЯ: «сходи по адресу p»
```

Один символ, два совершенно разных смысла. Компилятор их различает по контексту
(объявление или выражение), а человек путается. Привычка: видишь `*` в строке
объявления типа — это про тип. Видишь `*` в выражении — это «сходи по адресу».

### Реальный запуск

```
x      = 42
&x     = 0x7ffd879b5f64
p      = 0x7ffd879b5f64      ← p хранит ровно тот же адрес
*p     = 42
sizeof p = 8, sizeof *p = 4  ← сам указатель 8 байт, то, на что он смотрит, — 4
после *p = 100:  x = 100
```

Обрати внимание: `sizeof p` **всегда 8** на 64-битной машине, независимо от того,
указатель это на `int`, на `char` или на структуру. Адрес одной длины для всего.

## 3. Зачем указателю тип, если адрес всегда 8 байт

Тип говорит компилятору **две вещи**: сколько байт читать по этому адресу и как
их интерпретировать.

```c
int    *pi = (int*)&x;     // «тут лежит 4 байта, это int»
char   *pc = (char*)&x;    // «тут лежит 1 байт, это char»
double *pd = (double*)&x; // «тут 8 байт, это double» — прочитает мусор!
```

`void *` — адрес **без типа**. Его можно присваивать и сравнивать, но нельзя
разыменовать: компилятор не знает, сколько байт читать. Поэтому `malloc` в C++
требует явного приведения.

---

## 4. Указатель на указатель (твой P4)

```c
int x = 42;
int *p  = &x;    // p указывает на x
int **pp = &p;   // pp указывает на p
```

```
 pp ──→ p ──→ x
        (адрес p)  (адрес x)  (42)
```

- `pp` — адрес переменной `p`
- `*pp` — содержимое `p`, то есть адрес `x`
- `**pp` — содержимое `x`, то есть 42

Каждая звёздочка снимает **один уровень**. Реальный запуск:

```
pp     = 0x7ffd879b5f58
*pp    = 0x7ffd879b5f64  (это p)
**pp   = 100             (это x)
после **pp = 7:  x = 7, *p = 7
```

**Зачем это нужно в жизни:** когда функция должна изменить сам указатель, а не то,
на что он смотрит:

```c
void alloc(int **out) {          // хотим, чтобы у ВЫЗЫВАЮЩЕГО поменялся указатель
    *out = malloc(10 * sizeof **out);
}
int *data = NULL;
alloc(&data);                    // теперь data указывает на свежую память
```

А также для двумерных динамических массивов (`int **matrix`) — хотя там лучше
один непрерывный блок и индексация `i*cols + j`.

## 5. Зачем вообще указатели: функция не может вернуть несколько значений

Функция получает **копии** аргументов. Всё, что она с ними делает, остаётся внутри:

```c
void bad_swap(int a, int b)   { int t=a; a=b; b=t; }   // меняет КОПИИ
void good_swap(int *a, int *b){ int t=*a; *a=*b; *b=t; } // меняет ОРИГИНАЛЫ
```

```
bad_swap(a,b):    a=1 b=2     ← ничего не изменилось
good_swap(&a,&b): a=2 b=1     ← сработало
```

Отсюда **правило, которое решает 90% задач с указателями:**

> Хочешь, чтобы функция изменила твою переменную, — передай её **адрес**,
> а внутри работай через `*`.

И второе применение — **out-параметры**, когда функция должна вернуть несколько
значений (одно через `return`, остальные через указатели). Реальный пример:

```c
void unpack(uint32_t packed, unsigned *day, unsigned *month) {
    *day   =  packed       & 0x1Fu;   // записали РЕЗУЛЬТАТ туда, где лежит day вызывающего
    *month = (packed >> 5) & 0x0Fu;
}

unsigned d = 999, m = 999;
unpack((15u) | (7u << 5), &d, &m);
printf("day=%u month=%u\n", d, m);    // day=15 month=7
```

**Это ровно та схема, которая нужна в `unpack_date` из M2-T2.** Ты уже написал
`pack_date`; `unpack_date` — то же самое в обратную сторону, только результат
кладётся не в `return`, а по указателям `*day`, `*month`, `*year`.

В C++ вместо этого есть ссылки (`unsigned &day`) — та же суть, но без `&` при
вызове и без `*` внутри. Ссылка не может быть `NULL`, поэтому out-параметр через
ссылку безопаснее.

## 6. Массивы и указатели

```c
int arr[4] = {10, 20, 30, 40};
int *q = arr;          // то же, что &arr[0]: имя массива распадается в указатель
```

```
q ──→ ┌────┬────┬────┬────┐
      │ 10 │ 20 │ 30 │ 40 │
      └────┴────┴────┴────┘
      arr[0]  [1]  [2]  [3]
      q[0]   q[1] q[2] q[3]
```

Все четыре записи ниже дают **30**:

```
q[2]   ≡   *(q + 2)   ≡   2[q]   ≡   arr[2]
```

Реальный запуск:

```
arr[0]=10  *q=10  q[2]=30  *(q+2)=30  2[q]=30
q+1 - q = 1 (ptrdiff_t), адрес вырос на 4 байт
```

### Ключевой момент: арифметика указателей типизирована

`q + 1` — это **не «адрес плюс один байт»**, а «адрес плюс один **элемент**»,
то есть плюс `sizeof(int)` = 4 байта. Поэтому для `double *` тот же `q + 1`
сдвинется на 8. Именно благодаря этому `arr[i]` и `*(arr + i)` эквивалентны.

Разность двух указателей даёт **число элементов** между ними и имеет тип
`ptrdiff_t` (знаковый), а не `size_t`.

### Но массив ≠ указатель

| | `int arr[4]` | `int *q` |
|---|---|---|
| `sizeof` | 16 (весь массив) | 8 (адрес) |
| `&arr` | `int (*)[4]` — указатель на массив | `int **` |
| можно переназначить | ❌ `arr = ...` — ошибка | ✅ |
| знает свою длину | ✅ (в месте объявления) | ❌ |

Внутри функции, получившей массив как параметр, `sizeof` даст **8** — потому что
параметр уже указатель. Отсюда правило C: длину массива всегда передают отдельно.

## 7. Твоя ошибка в P2 — исправляю

Ты написал: *«наше p являет собой указатель — в нем записан просто индекс первого
(нулевого) элемента массива»*.

Не индекс, а **адрес**. Индекс — это номер элемента (0, 1, 2…), адрес — номер байта
в памяти (`0x7ffd879b5f64`). Разница принципиальная: из адреса можно вычесть адрес
начала массива и поделить на `sizeof`, тогда получится индекс. Сам по себе указатель
ничего про индексы не знает.

И вторая часть: *«если убрать звездочки, то по идее мы бы видели 1 и 2»*.

Нет. Без звёздочек напечатались бы **адреса**, а не элементы:

```c
printf("%p %p\n", (void*)p, (void*)(p + 1));   // 0x7ffd... 0x7ffd...
```

Причём печатать указатель через `%d` — **UB** (несовпадение спецификатора и типа),
нужен `%p` с приведением к `void*`. А «1 и 2» ты бы получил, если бы печатал
индексы — но их в указателе нет.

## 8. NULL

```c
int *np = NULL;      // указывает «никуда»
if (np == NULL) ...  // проверка
if (!np) ...         // то же самое, идиоматичнее
```

- Разыменование `NULL` → UB, на практике segfault (ASan напишет `SEGV`).
- `free(NULL)` и `delete nullptr` — **безопасны**, ничего не делают.
- Неинициализированный указатель — **не NULL**, а «дикий» (wild): в нём мусор,
  и проверка `if (p)` его не поймает. Объявляя указатель, сразу присваивай:
  `int *p = NULL;`.

## 9. `const` и указатели — читай справа налево

```c
const int *p;        // указатель на константу: *p менять НЕЛЬЗЯ, p — можно
int * const p;       // константный указатель: p менять НЕЛЬЗЯ, *p — можно
const int * const p; // нельзя ничего
```

Приём чтения: закрой звездочку и читай то, что справа от неё, потом то, что слева.

| Объявление | Смысл |
|---|---|
| `void f(const int *p)` | «я читаю твои данные и обещаю не менять» |
| `void f(int *p)` | «я буду менять твои данные» |
| `const char *s = "hi"` | строковый литерал, писать нельзя |
| `char *s = "hi"` | в C — плохая практика, в C++ — ошибка |

## 10. Каталог ошибок с указателями

| Код | Что не так |
|---|---|
| `int *p; *p = 5;` | дикий указатель, пишем в случайную память |
| `int *p = NULL; *p = 5;` | разыменование NULL → segfault |
| `int *f(){ int a[10]; return a; }` | возврат адреса локального массива — он умрёт при выходе |
| `int a[5]; a[5] = 1;` | выход за границы, UB (ловит ASan) |
| `free(p); *p = 1;` | use-after-free |
| `free(p); free(p);` | double free |
| `p = malloc(...); p = malloc(...);` | утечка: первый адрес потерян (твой A12) |
| `int* a, b;` | ⚠️ `a` — указатель, **`b` — обычный `int`**! Звёздочка привязывается к имени |
| `if (p = NULL)` | присваивание вместо сравнения, всегда ложно |
| `printf("%d", p)` | указатель через `%d` — UB, нужен `%p` |

Последняя предпоследняя строка — классика: `int* a, b;` объявляет один указатель и
один `int`. Поэтому в нормальном коде пишут по одному объявлению на строку или
используют `int *a, *b;`.

## 11. Как читать сложные объявления

Правило: **начинай от имени и иди по спирали вправо, потом влево.**

| Объявление | Как читать |
|---|---|
| `int *p` | p — указатель на int |
| `int **pp` | pp — указатель на указатель на int |
| `int a[10]` | a — массив из 10 int |
| `int *a[10]` | a — массив из 10 **указателей** на int |
| `int (*a)[10]` | a — указатель на массив из 10 int |
| `int (*f)(double)` | f — указатель на функцию (double) → int |
| `const char *s` | s — указатель на const char |
| `char * const s` | s — константный указатель на char |

Скобки меняют всё: `int *a[10]` и `int (*a)[10]` — разные типы.

/* 1 */ int x = 5, y = 9; int *p = &x, *q = &y;

## 13. Мини-шпаргалка

| Хочу | Пишу |
|---|---|
| узнать адрес переменной | `&x` |
| прочитать значение по указателю | `*p` |
| записать значение по указателю | `*p = 42;` |
| передать переменную так, чтобы её изменили | `f(&x)` + внутри `void f(int *v)` |
| вернуть из функции несколько значений | `return` + out-параметры через указатели |
| пройтись по массиву | `for (int *p = a; p != a + n; ++p) … *p …` |
| проверить указатель | `if (p)` или `if (p != NULL)` |
| объявить «пока никуда» | `int *p = NULL;` |

## A1 (недействителен) — целочисленное деление

Ответ был `3 1 3.5`. Суть: `7/2` в целых числах отбрасывает дробную часть → `3`;

вещественным → `3.5`.

**Замена — A1′:** что выведет этот код и почему именно так?
```c
printf("%d %d %d\n", 7 / 2 * 2, 7 % 2 * 2, -7 / 2);
```
*(проверено компилятором: ответ в конце файла, не подглядывай)*

### Заодно — таблица спецификаторов printf (ты написал, что «не совсем понимаю»)

| Спецификатор | Тип | Пример |
|---|---|---|
| `%d` или `%i` | `int` | `42` |
| `%u` | `unsigned int` | `42` |
| `%ld` / `%lld` | `long` / `long long` | `42` |
| `%zu` | `size_t` — **результат `sizeof` и размеры контейнеров** | `8` |
| `%c` | символ (`int`, преобразуется в `char`) | `A` |
| `%s` | строка (`char*`, печатается до `'\0'`) | `hello` |
| `%p` | указатель | `0x7ffd5c1a` |
| `%f` / `%g` | `double` (6 знаков / компактно) | `3.500000` / `3.5` |
| `%x` / `%X` | `unsigned` в шестнадцатеричном | `ff` / `FF` |
| `%%` | сам знак процента | `%` |

Ошибка в спецификаторе — это UB, а не «напечатается ерунда». Компилятор ловит такие
ошибки флагом `-Wformat=2` (у меня в `check.sh` он включён).

## A2 · `char c = 'A'` — ✅ верно по сути

Вывод: `65 B 1`.

Ты ответил правильно, но уточню три вещи:

1. `'A'` в **одинарных** кавычках — это **символьная константа** типа `char` в C++
   и типа `int` в C (это разница, запомни). `"A"` в **двойных** — **строковый литерал**,
   то есть массив из ДВУХ байт: `'A'` и завершающий `'\0'`.
2. Ты написал «объём памяти, занимаемый строкой 'A'». Тут не строка, а один символ —
   `sizeof` даёт 1. Для строки `"A"` было бы 2.
3. `sizeof` — **не функция**, а оператор. Он вычисляется на этапе компиляции
   (кроме VLA в C99). Скобки вокруг операнда не обязательны: `sizeof c` законно.

## A3 · неинициализированная переменная — ✅ верно

`int x; printf("%d", x);` → **неопределённое поведение**.

Уточнение к твоему «вероятно ошибка ваще»: программа при этом **не обязана** никак
сигнализировать. Варианты все законные: напечатает мусор из стека, напечатает 0,
упадёт, или компилятор вообще удалит этот код как «бессмысленный». Именно последнее
самое страшное — баг исчезает при включённой оптимизации и появляется в проде.

Локальные переменные в C/C++ **не инициализируются автоматически**. Правило: объявляя —
сразу присваивай. `int x = 0;` или `int x{};` в C++.

## A6 · массив и указатель — ❌ пробел (главный)

```c
int a[5] = {1, 2, 3, 4, 5};
printf("%d %d %d\n", a[0], *(a + 3), a[5]);
```
Ответ: `1`, `4`, и **UB** (выход за границы).

Мини-урок, который закрывает половину твоих пробелов:

1. **`a[i]` по определению языка равно `*(a + i)`.** Это не «похожие» записи, а одна
   и та же операция. Отсюда следует забавное: `3[a]` тоже скомпилируется и даст 4.
2. Имя массива в выражении **распадается** (array-to-pointer decay) в указатель на
   первый элемент. Поэтому `a + 3` — это адрес четвёртого элемента, а `*(a + 3)` = 4.
3. Допустимые индексы для `a[5]`: **0…4**. `a[5]` — это уже чужая память стека.
   ASan ловит это мгновенно: я проверил, выдаёт `stack-buffer-overflow` с номером строки.
4. Нюанс на будущее: указатель «на один элемент за концом» (`&a[5]`) **вычислять можно** —
   это требуется стандарту для работы циклов. Разыменовывать его нельзя.

## A7 · `sizeof` против `strlen` — ❌ пробел

```c
char s[] = "hello";
printf("%zu %zu %zu\n", sizeof s, strlen(s), sizeof(char *));
```
Ответ: **`6 5 8`**.

- `sizeof s` = 6 — массив из 5 символов **плюс `'\0'`**. Ноль-терминатор всегда входит.
- `strlen(s)` = 5 — функция считает символы до `'\0'`, сам терминатор не считает.
- `sizeof(char *)` = 8 — размер указателя на 64-битной машине.

И критически важное различие, которое ты встретишь в первой же лабе:

```c
char  s[] = "hello";   // МАССИВ 6 байт в стеке, можно менять: s[0] = 'H' — ОК
char *p   = "hello";   // УКАЗАТЕЛЬ на строковый литерал в read-only памяти
p[0] = 'H';            // UB, на практике segfault (проверил: SIGSEGV, exit 139)
```

Причём `sizeof p` даст **8**, а не длину строки — классический баг «посчитал размер
указателя вместо размера массива». Он же всплывает при передаче массива в функцию:
внутри функции `sizeof` от параметра-массива всегда даст размер указателя. Поэтому
в C длину массива **всегда** передают отдельным параметром — ровно так, как сделано
в задачах L1-T1 и L2-T2.

## A8 · `unsigned u = 3; if (u - 5 > 0)` — ✅ верно

Ответ: «больше». Твоё рассуждение про «пойдёт с другого конца диапазона» — правильное.

Только терминология: для `unsigned` это **не переполнение и не UB**, а определённая
стандартом арифметика **по модулю 2³²**: `3 - 5 = 4294967294`. Unsigned всегда ведёт
себя предсказуемо.

И именно поэтому он коварен. Реальный баг, который пишут все:

```cpp
for (size_t i = 0; i < v.size() - 1; ++i)   // если v пуст -> v.size()-1 = 18446744073709551615
```

Правило: **никогда не вычитай из `size_t`/`unsigned` без проверки.** Пиши
`if (n > 0) ... n - 1` или переноси вычитание в другую сторону: `i + 1 < v.size()`.

## A9 · `INT_MAX + 1` — ⚠️ результат угадал, суть нет

Вывод gcc: `-2147483648`. Твой ответ верный. Но:

> Для **знаковых** типов переполнение — **неопределённое поведение**, а не гарантированный
> переход «с другого конца диапазона». Это принципиальное отличие от A8.

Почему это важно на практике: компилятор имеет право считать, что «signed overflow never
happens», и выкинуть проверку. Классика:

```c
if (x + 100 > x) { /* ... */ }   // компилятор вправе заменить на if (true)
```

Как получить границы типа (ты написал, что не помнишь диапазоны):

| Тип | Байт | Минимум | Максимум |
|---|---|---|---|
| `char` | 1 | −128 | 127 |
| `short` | 2 | −32 768 | 32 767 |
| `int` | 4 (на всех современных десктопах) | −2 147 483 648 | 2 147 483 647 |
| `long` | **8 в Linux, 4 в Windows** | — | — |
| `long long` | 8 | −9 223 372 036 854 775 808 | 9 223 372 036 854 775 807 |

`long` — единственная настоящая ловушка: на Windows он 32-битный, на Linux 64-битный.
Поэтому в серьёзном коде используют `int32_t`, `uint64_t` из `<stdint.h>` — они
одинакового размера везде. Именно их мы будем использовать в M2.

Макросы: `<limits.h>` → `INT_MAX`, `INT_MIN`, `CHAR_BIT`. В C++ → `<limits>` →
`std::numeric_limits<int>::max()`.

## A10 · ссылка `int &x` — ❌ пробел (C++)

```cpp
void f(int &x) { x *= 10; }
int main() { int a = 1; f(a); std::cout << a; }
```
Ответ: **`10`**.

`int &x` — **ссылка**: второе имя для той же переменной, а не копия. Меняя `x`, меняем `a`.

Три способа передать переменную в функцию — запомни таблицу, это мост к модулю 3:

| Объявление | Вызов | Что внутри | Меняется ли оригинал |
|---|---|---|---|
| `void f(int x)` | `f(a)` | копия значения | нет |
| `void f(int &x)` | `f(a)` | ссылка на `a` | **да** |
| `void f(int *x)` | `f(&a)` | указатель, доступ через `*x` | **да** |

## A12 · `new` два раза — ❌ пробел

```cpp
int *p = new int(42);
p = new int(7);
std::cout << *p << "\n";
```
Вывод: **`7`**. Но в коде **утечка памяти**.

Что произошло:
1. `new int(42)` выделил 4 байта в куче, вернул указатель → сохранили в `p`.
2. `p = new int(7)` — перезаписали `p` новым адресом. **Первый адрес потерян.**
3. `delete p` (которого тут вообще нет) освободил бы только второй блок.
4. Первые 4 байта остались заняты до конца процесса, добраться до них невозможно.

Правило владения: кто выделил — тот и освобождает, и у каждого выделенного блока должен
быть ровно один владелец. В C++ эта проблема решается `std::unique_ptr` (модуль 9) —
он вызывает `delete` автоматически при выходе из области видимости.

Это ровно та тема, где у тебя провал по самоотчёту, и она будет ядром модуля 4.

# Контрольные вопросы на замену (ответь в `solutions/notes/probes.md`)

Все проверены компилятором. Сначала предскажи, потом можешь проверить.

**P1.** Чем отличаются эти две программы и что каждая напечатает?
```c
printf("%zu %zu\n", sizeof("A"), sizeof('A'));   /* C   */
```
```cpp
std::printf("%zu %zu\n", sizeof("A"), sizeof('A'));  // C++
```

**P2.**
```c
int a[3] = {10, 20, 30};
int *p = a;
p++;
printf("%d %d\n", *p, *(p + 1));
```

**P3.**
```c
int a[4] = {1, 2, 3, 4};
int *p = a;
printf("%zu %zu\n", sizeof a, sizeof p);
```
Почему числа разные, если `p` и `a` в выражениях часто взаимозаменяемы?

**P4.**
```c
int x = 5;
int *p = &x;
int **pp = &p;
printf("%d\n", **pp);
```

**P5.** Что произойдёт при запуске и почему?
```c
char *s = "hi";
s[0] = 'H';
printf("%s\n", s);
```

**P6.** Сколько итераций сделает цикл и чем это закончится?
```c
for (size_t i = 5; i >= 0; --i) printf("%zu ", i);
```

**P7.** Что напечатает и почему компилятор не выдаст ошибку?
```c
int a[5] = {1, 2, 3, 4, 5};
printf("%d\n", a[5]);
```

- **A1′:** `6 2 -3`. `7/2*2` = `3*2` = 6 (операции одного приоритета идут слева направо).

  массива в C/C++ **не проверяется** — ни на этапе компиляции, ни в рантайме.

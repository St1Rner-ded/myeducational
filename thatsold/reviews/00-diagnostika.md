## Часть B. Задачи на код

### Общие правила для всех задач

* Решай **на том языке, на котором задача помечена**: `.c` (C11) или `.cpp` (C++20).
* Бери готовую заготовку из `cpp-course/stubs/` — там уже написаны тесты в `main()`.
  **Меняй только тело помеченной `TODO` функции.** Тесты не правь (иначе проверка теряет смысл).
* Компилируй со строгими флагами, warnings не игнорируй:
  ```bash
  g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -g -fsanitize=address,undefined L0-T1.cpp -o t && ./t
  ```
* Программа должна напечатать `ALL TESTS PASSED`. Если тест упал — он назовёт номер.
* Сдай в репо: `solutions/L0/L0-T1.cpp` и т.д. Даже если не до конца работает — сдавай,
  я посмотрю на попытку.

### Уровень L0 — основы (ввод-вывод, ветвления, циклы, целочисленная арифметика)

**L0-T1 · Сумма цифр** (`.cpp`)
```
int sum_digits(long long n)
```
Сумма цифр числа по модулю. `123 → 6`, `0 → 0`, `-456 → 15`, `9999999999 → 90`.
*Крайние случаи:* ноль, отрицательные, `LLONG_MIN` (осторожно с `-n`!).

**L0-T2 · Простое число** (`.cpp`)
```
bool is_prime(long long n)
```
`2 → true`, `1 → false`, `0 → false`, `-7 → false`, `97 → true`, `999983 → true`.
*Подсказка-вопрос:* до какого числа достаточно перебирать делители и почему?

**L0-T3 · FizzBuzz в диапазоне** (`.cpp`)
```
void fizzbuzz(int from, int to)
```
Для каждого числа из `[from; to]` печатает по одному значению в строке:
`Fizz` (кратно 3), `Buzz` (кратно 5), `FizzBuzz` (кратно 15), иначе само число.
Проверь, что работает и для `from > to` (ничего не печатать), и для отрицательных.

### Уровень L1 — массивы, указатели «на пальцах», строки, функции

**L1-T1 · Разворот массива на месте** (`.c`)
```
void reverse_array(int *a, size_t n);
```
Без второго массива, за O(n). Пустой массив и `n == 1` не должны ломаться.

**L1-T2 · Палиндром «по-человечески»** (`.cpp`)
```
bool is_palindrome(const std::string &s);
```
Игнорируй регистр и все символы кроме букв (латиница).
`"A man, a plan, a canal: Panama" → true`, `"abc" → false`, `"" → true`.

**L1-T3 · Второе по величине** (`.cpp`)
```
int second_largest(const int *a, size_t n);
```
Второе **по значению** среди различных элементов, за один проход, без сортировки.
Если различных элементов меньше двух — вернуть `INT_MIN`.
`{1,2,3} → 2`, `{5,5,5} → INT_MIN`, `{3,1} → 1`, `{} → INT_MIN`, `{-5,-1} → -5`.

### Уровень L2 — память, указатели, структуры (ядро C)

**L2-T1 · Своя стандартная библиотека** (`.c`)
```
void   swap_ints(int *a, int *b);
size_t my_strlen(const char *s);
void   my_strcpy(char *dst, const char *src);
```
`<string.h>` не подключать. `my_strcpy` обязан ставить `'\0'`.
В отчёте ответь словами: почему `swap_ints` принимает указатели, а не значения?

**L2-T2 · Структуры и сортировка** (`.c`)
```c
typedef struct { char name[32]; int score; } Student;

void   sort_by_score(Student *s, size_t n);   /* по убыванию score */
double average_score(const Student *s, size_t n);
```
Сортировка любая (можно пузырьком), но **без выделения памяти**.
`average_score` для пустого массива → `0.0`.
В отчёте: чем `Student *s` в параметрах отличается от `Student s[]`?

**L2-T3 · Динамический массив** (`.cpp`)
```
int *create_range(int from, int to, size_t *out_len);
```
Возвращает массив, выделенный в куче, заполненный `from, from+1, ..., to`.
Длину кладёт в `*out_len`. Если `from > to` — вернуть `nullptr` и `*out_len = 0`.
Вызывающий освобождает память сам. Тесты в заготовке проверяют и это.
В отчёте: что произойдёт, если забыть `delete[]`?

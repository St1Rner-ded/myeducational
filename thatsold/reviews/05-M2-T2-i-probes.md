## 2. M2-T2 · флаги — все четыре верны

```c
if (bit > 31) return flags;
flags |= (1u << bit);
```

Защита от `bit > 31` на месте, `1u` вместо `1` — на месте. Ровно то, что требовалось.

### Замечание по переносимости — и оно прямо про твою Arduino

`1u` имеет тип `unsigned int`. На x86-64 это 32 бита, всё хорошо. Но **на AVR
(твоя Arduino Uno/Nano) `int` — 16 бит**, а 32 бита — это `long`:

| Платформа | `sizeof(int)` | `1u << 31` |
|---|---|---|
| x86-64 Linux/Windows | 4 | ✅ корректно |
| **AVR (Arduino)** | **2** | ❌ **UB**: сдвиг на 31 при ширине типа 16 |

Поэтому в переносимом коде для 32-битных флагов пишут:

```c
#include <stdint.h>
flags |= (UINT32_C(1) << bit);      /* UINT32_C(1) даёт константу ширины uint32_t */
/* или */
flags |= ((uint32_t)1 << bit);
```

`UINT32_C(1)` разворачивается в `1` или `1UL` в зависимости от платформы — ровно
то, что нужно. На PC разницы не заметишь, на AVR получишь тихий баг. Запомни:
**побитовая арифметика на микроконтроллере — всегда через `stdint.h` и макросы
`UINTn_C`**, никогда через голые `1` или `1u`.

Кстати, в Arduino-коде ты используешь `bitRead()` — она внутри делает то же самое,
и `byte` там = `uint8_t`, поэтому с 8-битными масками проблемы нет.

### `flag_test` — микро-упрощение

```c
if (flags & (1u << bit)) return 1;
return 0;
```
→
```c
return (flags & (UINT32_C(1) << bit)) != 0;
```

Результат сравнения уже есть 0 или 1. Приём «возвращай результат сравнения вместо
ветки if» ты уже применил в `is_prime` после моего замечания — тут то же самое.

## 3. M2-T2 · `pack_date` — работает, но два момента

```c
day   &= 0x0000001Fu;
month  = (month & 0x0000000Fu) << 5u;
year   = (year  & 0x007FFFFFu) << 9u;
uint32_t date = day + month + year;
return date;
```

Маски правильные, сдвиги правильные, тест на обрезание полей проходит. Но:

**1. `+` вместо `|`.** Здесь это работает, потому что поля не перекрываются —
маски гарантируют, что биты disjoint, и сложение совпадает с ИЛИ. Но `|` выражает
**намерение** («склеить поля»), а `+` — «сложить числа». Если однажды маска окажется
неверной и поля начнут пересекаться, `|` даст предсказуемый результат, а `+` —
перенос между разрядами, то есть тихую порчу соседнего поля. В побитовой работе
склейка полей — всегда `|`.

**2. Ты меняешь параметры.** `month = (month & 0xF) << 5` перезаписывает входной
параметр. Работает, но читается тяжело: невозможно понять, где значение ещё
«настоящее», а где уже сдвинутое. Чище:

```c
return (day & 0x1Fu) | ((month & 0xFu) << 5) | ((year & 0x7FFFFFu) << 9);
```

Одна строка, ни одна переменная не переназначена, все три поля видны сразу.

**3. Мелочь:** `<< 5u` — суффикс `u` у величины сдвига не нужен, сдвиг всегда
целочисленный. Не ошибка, но шум.

## 5. `probes.md` — разбор

### P1 ✅ и отдельный респект

Ты **написал обе программы и запустил их**, а не ответил по памяти. Именно так и
надо работать со всем, в чём не уверен. Результаты верные: C → `2 4`, C++ → `2 1`.

Про `stdio.h` против `cstdio` уточню: `#include <cstdio>` в C++ кладёт `printf`
в пространство имён `std` (и, как правило, также в глобальное), а `<stdio.h>` —
в глобальное. Поэтому `std::printf` требует `<cstdio>`. На практике в C++ чаще
пишут `<cstdio>` и пользуются `std::printf`, либо вообще переходят на `std::cout`.

### P2 ⚠️ две неточности

**«в нем записан просто индекс первого элемента»** — не индекс, а **адрес**.
Индекс — номер элемента (0, 1, 2), адрес — номер байта в памяти. Указатель про
индексы ничего не знает; индекс получается, если вычесть адрес начала и поделить
на `sizeof`.

**«если убрать звездочки, мы бы видели 1 и 2»** — нет, увидели бы **адреса**.
Причём печатать указатель через `%d` — UB, gcc с `-Wformat=2` ругается:

```
warning: format '%d' expects argument of type 'int',
         but argument 2 has type 'int *' [-Wformat=]
```

Правильно — `%p` с приведением к `void*`. Подробности в `theory/02-ukazateli.md` §7.

### P3 ✅ верно

Добавлю только, что распад массива в указатель **не происходит** в трёх случаях:
`sizeof a`, `&a` и инициализация массива строковым литералом. Это исключения,
которые стоит помнить.

### P4 — «это вообще ШТО»

`int **pp` — указатель на указатель. Разобран с картинкой памяти и реальным
выводом в `theory/02-ukazateli.md` §4. Коротко: каждая звёздочка снимает один
уровень, `**pp` — это `x`.

### P5 ⚠️ вывод верный, причина сформулирована сбивчиво

Ты написал: «мы попытались поменять read only и не const указатель, поэтому UB».

Точнее: UB происходит от **записи в строковый литерал**. Литерал `"hi"` лежит в
read-only сегменте памяти (`.rodata`), и попытка его изменить — неопределённое
поведение, на практике segfault (проверено: SIGSEGV, код возврата 139).

То, что указатель объявлен как `char *` без `const`, — **не причина UB, а причина,
по которой компилятор тебя не остановил**. В C такая запись допустима (исторически),
в C++ — ошибка. Лечится двумя способами:

```c
const char *s = "hi";   /* компилятор не даст записать — ошибка на этапе сборки */
char s[] = "hi";        /* это массив в стеке, записывать МОЖНО */
```

### P6 ⚠️ причина найдена верно, способ починки — нет

Диагноз правильный: тип беззнаковый, минимум 0, условие `>= 0` истинно всегда,
цикл бесконечный. gcc даже предупреждает: `-Wtype-limits: comparison of unsigned
expression in '>= 0' is always true`.

Но твоё «двигать по условию `> 0`» теряет ноль. Проверил все варианты:

| Цикл | Вывод | Комментарий |
|---|---|---|
| `for (size_t i = 5; i >= 0; --i)` | ∞ | UB-подобная ловушка |
| `for (size_t i = 5; i > 0; --i)` | `5 4 3 2 1` | **нуля нет** |
| `for (size_t i = 5; i-- > 0;)` | `4 3 2 1 0` | идиома, но печатает уже уменьшенное |
| `for (int i = 5; i >= 0; --i)` | `5 4 3 2 1 0` | ✅ знаковый тип — проще всего |
| `for (size_t i = 0; i < 6; ++i)` | `0 1 2 3 4 5` | ✅ идти вперёд — самый надёжный |

Правило: **обратный цикл по беззнаковому типу — всегда источник ошибок**. Либо бери
знаковый тип, либо иди вперёд.

### P7 ⚠️ наполовину

«для компилятора вызвать индекс 5, когда индексы есть только 0–4, это явное
ХЗ ЧЕ ДЕЛАТЬ» — ощущение верное, но вопрос был «почему компилятор **молчит**».

Ответ: **в C/C++ нет проверки границ массивов вообще** — ни на этапе компиляции,
ни в рантайме. Это осознанное решение ради скорости: `a[i]` компилируется в
`*(a + i)`, то есть в сложение адреса и чтение памяти. Никакой дополнительной
проверки. Компилятор в общем случае и не может доказать выход за границы — размер
массива часто неизвестен до рантайма.

Поэтому ловят это не компилятором, а **санитайзером**: `-fsanitize=address`
вставляет проверки вокруг каждого обращения и выдаёт `stack-buffer-overflow`
с номером строки. Отсюда и наше правило «всегда собирать с ASan на учёбе».

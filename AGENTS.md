# AGENTS.md — как работать в этом репозитории

Учебный репозиторий по **чистому C11** (`x86-64 Linux / WSL2 Debian`). Цель — понять язык
и память, а не просто получить работающий файл. Агент здесь **ревьюер и спарринг-партнёр**,
а не автор решения.

## 1. Железные правила

1. **Не решать задачу за пользователя.** Объяснять причину, задавать наводящий вопрос,
   показывать минимальный изолированный пример. Готовый код в его файл не вставлять,
   пока он явно не попросит.
2. **Язык — русский:** объяснения, комментарии в коде, сообщения коммитов.
3. **Каждое утверждение о числе или поведении — из реального запуска**, а не по памяти.
   Не уверен — собери и проверь.
4. **Не коммитить без явного разрешения.** Сначала показать `git diff`.

## 2. Стиль кода

Следовать тому, что уже есть в `thatsnew/`:

```c
int array_max (int *array, size_t asize) {
    int most = array [0];
    for (size_t i = 0; i < asize; ++i) {
        if (array[i] > most) most = array [i];
    }
    return most;
}
```

- K&R: открывающая скобка на той же строке, 4 пробела, пробел перед `(` в объявлениях.
- `size_t` для индексов и размеров; `int` для значений.
- Объявления — в начале блока или в `for`-init (C99+).
- `int main (void)` — не `int main ()`.
- Минимум `#include`. Пользователь сознательно обходится `<stdio.h>`/`<stdlib.h>` там,
  где можно; не тащить `<string.h>` «для удобства».

## 3. Сборка и проверка

Рабочая сборка (дома, WSL):

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion \
    -Wformat=2 -g -fsanitize=address,undefined file.c -o /tmp/t && /tmp/t
```

Строгая, перед коммитом (`-Werror`):

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion \
    -Wformat=2 -Werror file.c -o /tmp/t && /tmp/t
```

- **Бинарник — только в `/tmp`** или `-o t` (он в `.gitignore`). Никаких ELF в репозитории.
- **Ноль предупреждений** — обязательное условие, а не пожелание.
- В колледже (MinGW-w64) ASan обычно не линкуется: UBSan проверять отдельно,
  компенсация — `-fanalyzer`. Подробности — `SPRAVOCHNIK.md` §7.2.1.
- Ввод-вывод: боевая версия задачи читает **stdin**, а не генерирует данные сама.
  Генератор — только под `-DSELFTEST` или в отдельном стенде.

## 4. Куда что писать

| Что | Куда |
|---|---|
| Новая грабля, пойманная на практике | `SPRAVOCHNIK.md` §9 — строка в таблицу «Симптом / Причина / Лечение» |
| Разбор задачи, код-ревью | `thatsold/reviews/` |
| Теория, конспект | `thatsold/theory/` |
| Черновики и эксперименты | `thatsold/scratch/` |
| Рабочие решения | `thatsnew/` |

Правило справочника: любое изменение — **bump версии в шапке + запись в §12 «Журнал изменений»**. Версия справочника обновляется **только один раз за коммит**.
Формулировка граблей должна содержать конкретный воспроизведённый случай
(вход → неверный выход → правильный выход).

## 5. Что не трогать

- `thatsold/` — архив прошлых итераций. Только чтение, если не попросили обратного.
- `SPRAVOCHNIK.md` — не переписывать разделы целиком; дополнять точечно, сохраняя структуру.
- Скомпилированные файлы (`*.out`, `t`, ELF без расширения) — в `.gitignore`, в коммит не идут.

# tests/ — указатели «на ощупь»

Серия из шести маленьких самодостаточных C11-тестов, чтобы довести указатели
до состояния «ориентироваться как в воде». Каждый файл:

- собирается **сам по себе** (никаких общих хедеров, никаких зависимостей
  между файлами),
- печатает реальные адреса и вычисленные шаги — смотри, а не верь на слово,
- сам себя проверяет: код возврата **0** — всё, как ты думаешь; **1** — где-то
  модель в голове расходится с реальностью, смотри на строку `FAIL:`.

## Порядок чтения (строго по порядку)

| # | Файл | Вопрос, который он закрывает |
|---|---|---|
| 01 | `01-addresses.c` | Что вообще лежит в указателе? `&`/`*`, `**`, `sizeof` каждого уровня |
| 02 | `02-array-decay.c` | Почему массив «становится» указателем и где теряется длина |
| 03 | `03-pointer-arithmetic.c` | Сколько байт идёт `p + 1`? Что такое `q - p`? |
| 04 | `04-matrix.c` | `int[2][3]`: строки, `int (*)[3]`, плоский `malloc` |
| 05 | `05-strings.c` | Строки = `char*` + `\0`; `char[]` против `char*` |
| 06 | `06-out-params.c` | int / int\* / int\** в аргументах; head-паттерн из `2nd.c` |

Связь со своим кодом: темы 06 — прямая мотивация `append (Node **head, ...)`
в `first/1st.c`, `second/2nd.c`; тема 05 — будущий палиндром в `olimp/ol8`.

## Как запускать

Вариант 1 — по одному файлу (рекомендую начать так):

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion \
    -Wformat=2 -g -fsanitize=address,undefined \
    01-addresses.c -o /tmp/t && /tmp/t
```

Вариант 2 — прогнать все шесть скриптом:

```bash
./run.sh
```

Скрипт `run.sh` собирает каждый файл строгими флагами, запускает со
санитайзерами, считает, сколько тестов упали, и в конце печатает вердикт.

## Домашка после каждого файла

Не «прочитать и закрыть», а сделать то же самое **на бумаге**:

1. **01** — нарисовать три ячейки (`x`, `p`, `pp`) стрелками: от `pp` через `p`
   к `x`. Потом — после `p = &y` — перерисовать заново. Если рисунок получается
   с первого раза — файл закрыт.
2. **02** — ответить без компилятора: почему `sizeof a / sizeof a[0]` даёт длину,
   а `sizeof arr` внутри `f` — 8? (ответ: распад массива)
3. **03** — посчитать вручную, на сколько байт сдвинется `double *` при `+1`
   (подсказка: sizeof double), и только потом проверить машиной.
4. **04** — нарисовать на бумаге «ленту из 6 ячеек» и пометить, где лежат
   `m[1][2]` при плоском `malloc`.
5. **05** — объяснить одной фразой, чем `char s[] = "x"` отличается от
   `char *p = "x"` (подсказки: sizeof, где лежат данные, можно ли менять).
6. **06** — перерисовать из `2nd.c` момент `append(&head, ...)` для ПУСТОГО
   списка: где `head`, где копия параметра, что делает `*head = new_node`
   и почему без `**` это не сработало бы.

Правило: где не получилось нарисовать/ответить с первого раза — это и есть
точка, где «ориентация как в воде» ещё не собрана.
